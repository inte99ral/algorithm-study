## C 스타일 캐스팅

```c
(int) i
```

&nbsp; 가장 오래된 방식으로, C 언어에서 그대로 넘어온 문법입니다. 괄호를 타입 이름에 씌우면 끝입니다. 타이핑이 빠르고 간결합니다.

&nbsp; 일단 그냥 타입에 맞추라는 식의 강제 명령이라서, 위험한 변환(예를들어 포인터 타입을 정수로 바꾸기 등)도 가리지 않고 수행하려 합니다. 나중에 코드에서 캐스팅 부분을 찾기가 매우 어렵습니다.

## c++ 함수 스타일 캐스팅

```cpp
int(i)
```

&nbsp; C++에서 도입된 방식으로, 마치 생성자를 호출하는 것 같은 모양을 띕니다.

&nbsp; 타입을 함수처럼 쓰고 값을 괄호 안에 넣습니다. 타입 이름이 두 단어 이상인 경우에는 사용할 수 없습니다. 예를 들어 unsigned int 같은 경우, unsigned int(i)는 오류가 나며, 반드시 c 스타일 캐스팅으로 `(unsigned int)i` 라고 써야 합니다.

## 명시적 캐스트 연산자

&nbsp; 가장 권장되는 방법입니다. C++에서는 위 두 방식보다 더 안전하고 명확한 명시적 캐스트 연산자 사용을 강력히 권장합니다. 

&nbsp; 캐스트 연산자를 사용하면 컴파일 타임에 논리적으로 말이 안 되는 변환은 미리 막을 수 있습니다. 또한 코드 안에서 `..._cast` 라는 단어는 눈에 확 띄기 때문에, 어디서 타입 변환이 일어나는지 찾기 쉽습니다.

&nbsp; 디버깅 시에도 편하며 팀 단위 프로젝트 시에 "나는 지금 데이터 손실 위험이 있음을 알고도 이 변환을 하겠다" 는 의도를 동료 개발자에게 명확히 전달할 수 있습니다.

### static_cast

```cpp
static_cast<int>(i);
```

가장 범용적으로 사용되는 캐스트입니다. <u><b>컴파일 타임<b/><u/>에 타입 체크를 수행합니다.

`int ↔ float` 같은 상황처럼 논리적으로 연관된 타입 간의 변환에 쓰기 좋습니다.

`char* ↔ int*` 같이 전혀 관계없는 포인터끼리의 변환은 <u><b>허용하지 않습니다</b></u>.

상속 관계에서 부모를 자식으로 바꿀 때는(Downcast), 적합한 지 확인하지 않으므로 위험할 수 있습니다.

### dynamic_cast

안전한 상속 구조 변환을 위해 사용됩니다. <u><b>런타임(실행 중)<b/><u/>에 타입을 확인합니다.

`부모 클래스 ↔ 자식 클래스`, 즉 부모 클래스 포인터를 자식 클래스 포인터로 변환할 때(Downcast) 주로 사용합니다. 

다형성으로 연결되는 관계는 프로그램이 돌아가면서 상속되는 런타임 시점에서 결정되기 때문에 런타임 시점에서 RTTI(Runtime Type Information, 실시간 타입 정보) 확인하는 dynamic_cast 가 더 안전합니다. 문제 발생 전 nullptr 리턴을 보장하므로 nullptr 체크만 해주면 됩니다.

조건으로 부모 클래스에 최소 하나 이상의 가상 함수(virtual)가 있어야 합니다 (다형성 필요).

### reinterpret_cast (재해석 캐스팅)

가장 위험하고 강력한 캐스트입니다. 비트 단위로 데이터를 재해석합니다. 컴파일러는 아무런 검사도 수행하지 않고, 적힌 그대로 비트를 해석합니다.

`int ↔ int*`, `char* ↔ int*` 처럼 전혀 상관없는 타입 간의 변환이 가능합니다.

잘못 사용하면 즉시 프로그램이 뻗어버릴(Crash) 수 있으므로 하드웨어 제어나 특수 상황에서만 씁니다.

### const_cast (상수성 제거)

포인터나 참조자의 const 또는 volatile 속성을 잠시 제거할 때 사용합니다.

상수 객체를 상수 기능이 없는 외부 함수에 전달해야 할 때 사용합니다.
