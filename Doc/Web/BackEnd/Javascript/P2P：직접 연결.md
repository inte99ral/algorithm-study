# P2P (Peer-to-Peer)：직접 연결

## 설명 1

&nbsp; co-op 게임이나 채팅 기능처럼 PC1 과 PC2 를 연결시키는 서비스는 일반적으로 중앙서버를 중심으로 하여 데이터만 전달합니다.

`PC1 <---> 중앙서버 <---> PC2`

이런 구조의 장점으로는 방화벽, NAT, 보안, 인증, 동기화 문제 해결이 쉽다는 것이 있습니다. 하지만 단점으로 서버 부하, 지연(latency) 증가, 서버 운영비등의 문제가 있습니다.

<br />

&nbsp; 이런 단점들을 해결하기 위해서 두 컴퓨터를 직접 연결해버리는 밑의 구조도 있습니다.

`PC1 <---> PC2`

이는 이론상은 가능합니다. 하지만 공유기 포트포워딩, 보안, 매칭 연결 문제로 인하여 불가능에 가깝습니다.

<br />

위와 같은 상황에서 만들어진 절충안이 P2P + Signaling 서버 구조입니다.

중앙 서버는 단 최초 연결(신호 교환) 에만 쓰이며, 이후에는 `PC1 <---> PC2` 직접 연결 (UDP Hole Punching)

WebRTC, Steam Networking Sockets, ENet + NAT Punching 등이 이 방식을 사용합니다.

## 리슨 서버 형식

-   [대표예시. 라스트맨스탠딩](https://pheonise.itch.io/last-man-standing)

게임사가 중심에서 중앙 서버로 유저를 연결하는 것이 아니라 게임의 방을 판 클라이언트가 직접 호스트가 되어 직접 서버 역할을 취하게 할 수 있습니다. 네트워크 프로그래밍에서는 P2P(Peer-to-Peer) 방식의 일종인 리슨 서버(Listen Server) 구조라고 부릅니다.

내부적으로 다음의 기술적 단계를 거쳐서 구현가능합니다.

-   (1) 소켓 프로그래밍(Socket Programming)

네트워크로 데이터를 주고받기 위한 가장 기본적인 프로그래밍 방식입니다.

서버(Host Client): 특정 포트(예: 12345)를 지정해 소켓을 열고, "이 주소로 들어오는 연결을 받겠다(Listen 상태)"고 설정합니다.

클라이언트(Other Client): 호스트 IP 주소와 포트 번호를 지정해 "연결해줘(Connect요청)"라고 신호를 보냅니다.

-   (2) UDP 또는 TCP 프로토콜

"라스트맨스탠딩"처럼 실시간으로 캐릭터가 움직이고 싸우는 게임은 보통 UDP(User Datagram Protocol)를 주로 사용합니다.

TCP는 데이터가 잘 갔나 일일이 확인해서 느리지만 정확하고, UDP는 확인 절차 없이 데이터를 총알처럼 빠르게 보내기 때문에 실시간 액션 게임에 필수적입니다. 대신 끊김이나 데이터 유실을 보정하는 코드가 게임 내에 들어가야 하는 것을 명심해야합니다.

-   (3 - 1) 포트 포워딩(Port Forwarding) 또는 DMZ

호스트가 된 클라이언트에게 다른 클라이언트가 요청을 보내기 위해서 호스트가 외부IP 에게 길을 열어주는 것이 포트 포워딩입니다.

-   (3 - 2) NAT 홀펀칭(NAT Punchthrough)
